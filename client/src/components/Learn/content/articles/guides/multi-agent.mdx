## What it is

A multi-agent workflow divides work between agents instead of asking one agent to do everything. In Agent Builder, Advanced has a Multi-agent orchestration section with these options:

- Handoffs: transfer the conversation to a specialist agent
- Subagents: spin up helper agents to handle subtasks

## Why it matters

One agent with many skills works for straightforward, linear tasks. As a workflow grows, a single agent’s instructions get long and it can lose track of them. Specialist agents each work with a focused set of instructions.

## Handoffs

A handoff transfers the conversation from one agent to a specialist agent when a task needs different expertise. Each handoff includes a description of when to transfer and the content to pass on.

To set one up, open Advanced in Agent Builder, select Add handoff agent and describe when to use it.

## Subagents

A subagent is a smaller, specialist agent that the main agent calls on to complete one part of the work. The main agent receives your request, decides how to handle it and passes subtasks to subagents. Subagents run in their own focused context, and only a summary comes back to the main agent. You only talk to the main agent.

Take the request “Summarise this contract and flag any unusual payment terms”:

1. The main agent passes the contract to a document reading subagent, which extracts and structures the text.
2. It passes that output to a risk analysis subagent, which identifies unusual payment terms.
3. The main agent combines both outputs and returns a summary to you.

An agent can also delegate focused subtasks to a fresh copy of itself, using the Allow self-spawn option. Enable subagents in Advanced turns the feature on for an agent.

## One agent or several

Both approaches work. They suit different situations.

| | One agent with many skills | Main agent with subagents |
|---|---|---|
| Best for | Straightforward, linear tasks | Complex, multi-step workflows |
| Context | All skills share one context, so quality can drop as the task grows | Each subagent works in its own focused context |
| Specialisation | One set of instructions covers everything | Each subagent has a dedicated purpose and tailored instructions |
| Reliability | The model can lose track of instructions in a long workflow | Clear task boundaries reduce errors |
| Maintenance | Changing one part can affect the whole agent | You can update subagents independently |
| Reuse | The agent is self-contained and hard to repurpose | A subagent built for one workflow can serve others |

Use one agent with several skills when the task is straightforward and follows a clear sequence. Consider subagents when:

- The workflow has distinct phases that need different expertise
- Output quality matters and you want each step handled with focus
- You want to reuse parts of the workflow in other agents
- The task is likely to grow more complex over time

Long instructions that try to make one agent do many things well are a sign to split the work.
