## What it is

A skill is a set of written instructions for doing one task the same way every time. It packages instructions, reference material and optional supporting files so MyAssist can complete a repeatable task consistently. A skill tells the model how to work. It doesn’t change which model runs.

## Why it matters

A skill moves a proven method out of one person’s head and into MyAssist. Anyone who uses the skill gets the same approach. The result depends less on who is asking.

## Understand your skills library

Select **Skills** from the side menu to open the library. It has three views:

- **Created by me**: skills you’ve created
- **Shared**: skills other people have shared with you
- **Public**: skills shared publicly

Each skill has an **Active** toggle. Turn a skill on to make it available in your chats.

## Trigger a skill in a chat

A skill’s **Invocation Mode** decides how it runs:

- **Auto**: MyAssist applies the skill when it’s relevant to your request
- **Manual**: the skill runs only when you invoke it
- **Both**: MyAssist can apply it automatically, and you can invoke it yourself

To invoke a skill, type `$` in the message box and select the skill by name. Only active skills appear in the list.

## Create a skill

Creating a skill involves four decisions: which route to use, what the skill does, how to write it down and how to test it.

Write skill instructions suits a straightforward skill that needs no supporting files. Upload a skill suits one that relies on references, templates, assets or scripts.

The Skill Builder skill (`myassist-skill-builder`) drafts a first version, including the SKILL.md file. The Skill Refiner skill (`myassist-skill-refiner`) reviews and strengthens an existing skill. Check and tailor the result before you create or upload it.

### Plan before you create

Answer these six questions before you write anything:

<Steps>

1. Define the outcome: state the task the skill should complete and the value it provides.
2. Set the trigger: explain when to use the skill and, where useful, when not to.
3. Identify the inputs: list what the user must provide, such as an audience, topic, source file or format.
4. Design the workflow: break the task into clear steps and decision points. Tell the skill to ask for missing information instead of guessing.
5. Describe the output: specify the structure, tone, level of detail and any mandatory sections or templates.
6. Add guardrails: include source boundaries, quality checks, privacy considerations and constraints that keep the response fit for purpose.

</Steps>

### Write instructions in Markdown

Markdown is a lightweight way to structure plain text. Use headings to separate ideas, numbered lists for ordered workflows and bullet lists for options or checks. Keep each instruction specific and testable. The [GCSE method](/learn/articles/write-an-effective-prompt#the-gcse-method) helps here too.

A SKILL.md file works best with these sections:

- Purpose and when to use it
- Required inputs
- A two-step workflow
- Expected outputs
- Response guidelines
- Ground rules and constraints

### Create in MyAssist

<Steps>

1. Select **Skills** from the side menu to open Skills.
2. Select **Create**, then choose **Write skill instructions**.
3. Enter a short, descriptive skill name in lowercase words separated by hyphens. Example: `brand-guidelines`.
4. Enter a skill description that says what the skill does and where to use it. Example: Apply brand guidelines to presentations and documents.
5. Write the instructions in Markdown. Complete each section of the template, replace all placeholder text and remove guidance you don’t need. Ask MyAssist to refine the draft if you want a second pair of eyes.
6. Select **Create**.

</Steps>

### Package and upload

Create the skill as a folder with a required SKILL.md file and any supporting folders.

[TO BE CONFIRMED: folder structure image needed from the MyAssist team]

<Steps>

1. Open the root folder and confirm that SKILL.md sits directly inside it.
2. Check that file and folder names exactly match any paths used in SKILL.md.
3. Remove drafts, duplicate files and anything the skill doesn’t need.
4. Compress the root folder into a single `.zip` file. Opened, the ZIP contains one skill folder with SKILL.md and any supporting folders inside it.
5. In MyAssist, open **Skills** and choose **Upload a Skill**. Select the ZIP file, then follow the prompts to validate and create the skill.

</Steps>

### Test and refine

Try realistic scenarios, including incomplete or ambiguous requests. Adjust the instructions wherever the results vary, and test again.

## Share a skill

<SharingNote />

<Steps>

1. Select **Skills** from the side menu to open Skills.
2. Select **Created by me** and open the skill you want to share.
3. Select **Share**.
4. Search for the people you want to share with, then select them.
5. Assign a permission level: **Viewer**, **Editor** or **Owner**. People can use the skill based on the permission you grant.
6. Select **Save Changes**.

</Steps>

People you share with find the skill under **Shared** in **Skills**. They may need to turn it on by setting the **Active** toggle.
