## What it is

A skill packages written instructions, reference material and optional supporting files. MyAssist then completes a specific task the same way every time. It tells the model how to work, not which model to use.

## Why it matters

A skill moves a proven method out of one person’s head and into MyAssist. Anyone on the team can use it and get the same result, however they phrase the request.

## Understand your skills library

Select Skills from the side menu to open your skills library. You’ll see three tabs:

- Created by me: skills you’ve built
- Shared: skills other people have shared with you
- Public: skills shared publicly

Each skill has an Active toggle. Switch it on to make the skill available in your chats.

## Use a skill in a chat

Each skill has an Invocation Mode that controls when it runs:

- Auto: MyAssist applies the skill when it’s relevant to your request
- Manual: the skill runs only when you invoke it
- Both: MyAssist can apply it automatically, and you can invoke it yourself

To use a skill manually, type `$` in the message box and select the skill by name. Only skills you’ve switched on appear in the list.

## Create a skill

Creating a skill has four stages: choose how to build it, plan what it does, write the instructions, then test it.

Write skill instructions suits a skill that needs no extra files. Upload a skill suits a skill that relies on reference documents, templates or other supporting files.

MyAssist has two built-in skills to help you:

- Skill Builder (`myassist-skill-builder`): drafts a first version of your skill, including the SKILL.md file
- Skill Refiner (`myassist-skill-refiner`): reviews and improves a skill you’ve already written

Check and adjust the output before you save or upload it.

### Plan before you create

Answer these six questions before you write anything:

| Stage | Question |
|---|---|
| Outcome | What does the skill do, and why is it useful? |
| Trigger | When should the skill run, and is there anything it shouldn’t be used for? |
| Inputs | What does the user need to provide, such as an audience, topic, file or format? |
| Workflow | What are the steps, and what should happen if information is missing? Tell the skill to ask rather than guess. |
| Output | What should the result look like, including structure, tone, level of detail and any required sections or templates? |
| Guardrails | What limits should the skill respect, such as privacy, source boundaries and quality checks? |

### Write instructions in Markdown

Markdown is a lightweight way to format plain text with headings, numbered lists and bullet points. Use headings to separate ideas, numbered lists for step-by-step workflows and bullet points for options or checks. Write each instruction as you would a prompt: specific, testable and grounded in the [GCSE method](/learn/articles/write-an-effective-prompt#the-gcse-method) helps here too.

A SKILL.md file works best with these sections:

- What the skill does and when to use it
- What the user needs to provide
- A step-by-step workflow
- What the output should look like
- How to write the response
- Rules and limits the skill must follow

### Create in MyAssist

<Steps>

1. Select **Skills** from the side menu to open Skills.
2. Select **Create**, then choose **Write skill instructions**.
3. Enter a short, descriptive skill name in lowercase words separated by hyphens. Example: `brand-guidelines`.
4. Enter a skill description that says what the skill does and where to use it. Example: Apply brand guidelines to presentations and documents.
5. Write the instructions in Markdown. Complete each section of the template, replace all placeholder text and remove guidance you don’t need. Use the Skill Refiner skill (`myassist-skill-refiner`) to review and strengthen the draft before you save it.
6. Select **Create**.

</Steps>

### Package and upload

Create the skill as a folder with a required SKILL.md file and any supporting folders.

[TO BE CONFIRMED: folder structure image needed from the MyAssist team]

<Steps>

1. Open the root folder and confirm that SKILL.md sits directly inside it.
2. Check that file and folder names exactly match any paths used in SKILL.md.
3. Remove drafts, duplicate files and anything the skill doesn’t need.
4. Compress the root folder into a single `.zip` file. When you open the ZIP, it should contain one folder with SKILL.md and any supporting files inside it.
5. In MyAssist, open **Skills** and choose **Upload a Skill**. Select the ZIP file, then follow the prompts to validate and create the skill.

</Steps>

### Test and refine

Test with realistic examples, including ones where the input is incomplete, unclear or at the edge of what the skill covers. Where the output isn’t right, adjust the instructions and test again.

## Share a skill

<SharingNote />

<Steps>

1. Select **Skills** from the side menu to open Skills.
2. Select **Created by me** and open the skill you want to share.
3. Select **Share**.
4. Search for the people you want to share with, then select them.
5. Choose a permission level: Viewer, Editor or Owner.
6. Select **Save Changes**.

</Steps>

People you share with find the skill under Shared in their skills library. They may need to switch it on with the Active toggle before they can use it.
